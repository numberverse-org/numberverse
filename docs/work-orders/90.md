# #90 — Privacy: data-minimization audit

**Status:** ✅ merged (#427) — rides the next patch release as housekeeping.

## Problem

Nothing documented *what* the app stores, on-device or on the API, or *why* —
so a future contributor could add a needless field (or worse, a tracker) with
no guardrail and no paper trail.

## Fix

`docs/PRIVACY.md` — the full data-minimization audit:

- **On-device table** — every localStorage key (`nv_parent_token`,
  `nv_device_secret`, `nv_kid_map`, `nv_play_minutes`, `nv_lang`,
  `nv_parent_aggregate_opt_in`, …) with what / why / minimization. Nothing
  stores photos, contacts, location, or browsing data.
- **API table** — every Postgres table (`profiles`, `kids`, `sessions`,
  `learning_stories`, `progress_events`, `subscriptions`, …) with columns,
  why, and the PII flag.
- **Findings** — every field is either required for the app's function or
  already minimized. The only deliberate PII is parent-entered (`email`,
  `kids.name`) and deletable (CASCADE). `sessions.ip`/`user_agent` flagged for
  bounded retention. `learning_stories.context` is redacted server-side (#270).
  Zero analytics (enforced by #92 + Oracle Privacy Steward).
- **Oracle review** — Privacy Steward (`l1_privacy`) verified CLEAN.
