# #270 — Privacy: Kotha story context redaction

**Status:** ✅ released in 0.26.13 (2026-08-13)

## Problem

Kotha story `context` envelopes (`{ reason, message, fingerprint,
wrongAnswer, source }`) travel from the kid app to `POST /api/v1/stories`
and are stored verbatim. Nothing guaranteed a PII-shaped string couldn't ride
in — the envelope is "privacy-scrubbed by construction" in the schema doc but
there was no enforcement at the write boundary.

## Fix

Redact at write, server-side, before storage:

- `apps/api/app/scrub.py` → `redact_context()` — deep-walks the context dict
  (nested dicts/lists, str leaves redacted for PII; non-str leaves preserved;
  caller's dict never mutated).
- `apps/api/app/routers/progress.py` — `record_stories` now stores
  `redact_context(s.context)` instead of `s.context` raw.
- Unit tests cover deep/nested/list/immutability cases.

## Files
- `apps/api/app/scrub.py` — `redact_context`
- `apps/api/app/routers/progress.py` — apply at write
- `apps/api/tests/test_scrub.py` — context tests
