# #264 — Guardrail: no-network fallback verification test

**Status:** ✅ done (merged — issue CLOSED; e2e verified live)

## Problem

Offline behavior was documented manually (docs/OFFLINE.md) but nothing
automatically proved "the app runs with zero network on launch".

## Done-when (from the issue)

- [x] **Cold + warm test** — `e2e/offline.spec.ts` (Playwright, chromium)
      verifies BOTH: cold = install online once → offline reload renders with
      the launch-critical shell served from the SW precache; warm = revisit
      straight offline, same guarantee. Runs against the LIVE deployed app
      (the real artifact), CI job `offline-e2e`.
- [x] **No launch network calls** — the assertion model is the honest one: a
      SW cache hit still emits a CDP request but SUCCEEDS offline, so the test
      asserts every FAILED request is one of the two documented runtime-only
      features (neural-voice model download, Google sign-in button) — every
      other offline failure is a regression. The launch-critical path (document,
      `/assets/`, fonts, icons, manifest, favicon) must all succeed from cache.
