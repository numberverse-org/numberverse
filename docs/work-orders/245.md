# Work Order #245 — Parent: share-card deep link per kid

**Status:** DONE · **PR:** #559 · **Branch:** feat/245-share-link · **Merge:** main

## Problem
The WhatsApp weekly share card had no link — a friend/relative saw text but had
no way to "see the week" for themselves. A naive `?kid=<uuid>` link would have
leaked the kid's identity to anyone who opened it.

## Fix
The share card now carries a **unique, private, anonymous deep link per kid**.

- **Unique link per kid** — each kid gets an opaque, unguessable share token
  (24-byte URL-safe, `secrets.token_urlsafe`), minted on the parent's first
  share and stored on `kids.share_token` (unique, nullable → auto-migrated).
  The weekly "Share on WhatsApp" button mints it, appends
  `🔗 See the week: <link>` to the card, and also shows the link in the portal
  with a Copy button.
- **No personal data leak** — the link opens a PUBLIC snapshot endpoint
  (`GET /share/{token}`) that returns ONLY aggregates: rounds, minutes,
  correct %, active days, mastered count, top game. No name, avatar, kid id,
  email or skill ids. Unknown tokens → 404 (a guessed link finds nothing), and
  the token is only ever served to the authenticated parent.
- **No tracking** — the share page makes exactly one fetch; no analytics, no
  pixels. The FastAPI route is auth-free but the token IS the key.
- **Static-export friendly** — the portal builds with `output: "export"`, so
  the public page is a static route (`/share` reading `?t=<token>`), not a
  dynamic segment.
