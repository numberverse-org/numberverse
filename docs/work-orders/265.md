# #265 — Security: invalidate sessions on password change

**Status:** ✅ done (merged — issue CLOSED)

## Problem

A changed password should kill every login the old password created, on every
device — except the one making the change. The code existed in
`change-password` (revoke-all-others) but was UNTESTED — the security contract
had no proof.

## Done-when (from the issue)

- [x] **Code confirmed** — `change_password` already revokes every OTHER
      session server-side (a revoked sessions row kills the token in
      `get_current_profile`).
- [x] **Test added** — extracted the revocation rule into a pure, dependency-free
      helper (`app/session_guard.py::revoke_other_sessions`) used by BOTH
      `change-password` and `logout-all`, and wired a CI gate that proves:
      current session kept · others revoked · legacy-token caller revoked ·
      already-dead rows untouched · count accurate · empty/current-only safe.
