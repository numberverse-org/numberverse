# #355 — Haptic feedback on taps

**Status:** ✅ done (PR pending → issue CLOSE)

## Problem

On Android (Chrome) kids get no physical cue when they tap an answer. iOS
Safari has no `navigator.vibrate`, so the feature must degrade to silent there.
Acceptance: **respects system settings** · **off switch** · **optional**.

## Fix

Subtle haptic pulses piggyback the **shared audio path** — `pop()` / `bad()` /
`win()` / `click()` / `tada()` in `game/audio.ts` are called by EVERY scene and
DOM button, so one tiny hook reaches the whole app with zero per-scene changes.

- **Correct pop** → 12ms tick; **wrong nudge** → short double-pulse; **round
  win** → three-beat victory; **session tada** → sparkle burst; **UI click** →
  8ms tick. All tiny (≤50ms), never alarming.
- **Respects system settings** — the helper no-ops unless `navigator.vibrate`
  exists, so iOS Safari etc. never buzz; wrapped in try/catch so a
  focus-restricted browser can't break audio. Each pulse is optional by
  definition — no action ever depends on vibration.
- **Off switch** — a kid-safe 📳 **Tap vibration** toggle in Settings (Sound &
  voice card, beside Music), persisted as `nv_haptics` (default ON). Flipping
  it on fires a real sample pulse so the kid feels exactly what they enabled.
- **Locale-packed** (#131) — `settingsHaptics` EN + BN.
- **Offline** — localStorage + device API only.

## Files
- `apps/kid/src/game/audio.ts` — `haptic(pattern)` helper + hooks into
  pop/bad/win/click/tada
- `apps/kid/src/App.tsx` — `hapticsOn` state + `toggleHaptics` (with demo
  pulse), Settings row, Strings EN+BN
