# #114 — Offline: verify full offline on fresh install

**Status:** 🔜 in progress (PR open)

## Problem

Claimed the kid PWA works offline, but nothing had *proven* the shell +
precache survive a zero-network fresh install.

## Fix

Verification-only (no runtime code change): `docs/OFFLINE.md` records the
audit against the live build.

- **Test matrix** — cold (fresh install, online → precache once) and warm
  (offline relaunch → precache + `navigateFallback` serve the app). Live
  `sw.js` precaches **22 entries** (index.html, main JS 0.45 MB gz, CSS,
  Phaser engine, fonts, icons, sprites, manifest) with content-hash revisions.
- **No network calls on launch** — boot path (`main.tsx` → first App render)
  has zero `fetch`; the only sites outside `api.ts` are the voice-model
  download (first Bangla *use*, runtime-cached after) and the Google status
  probe (only when the button renders). `api.ts` is local-first with a
  persisted outbox and offline-degrading identity.
- **Known gap documented** — the ~110 MB neural voice is CacheFirst after the
  first online session; games are fully offline regardless.
