# Work order #1748 — Health endpoint returns a static ok without probing DB or background jobs
> milestone: v39 — deepthink sweep · branch: `feat/issue-1748`

## Acceptance criteria (from the issue)

## Where
apps/api/app/main.py:222

## Why it matters
GET /health (main.py:222-224) unconditionally returns {"status":"ok"}. It never opens a DB session, runs SELECT 1, or checks that the Kotha embed loop is alive, so a deployment with a dead database, an exhausted connection pool, or a crashed background task still reports green. Any uptime check or load balancer routing on /health will route traffic into a broken box.

## Suggested fix
Make /health perform a cheap liveness probe: await a SELECT 1 through SessionLocal, return 503 with a degraded reason (db|embed-loop) on failure. Keep it unauthenticated and dependency-light so it still works under load.

## Done when
- [ ] curl /health returns 503 when the database is stopped
- [ ] curl /health returns 200 with a db:ok field normally
