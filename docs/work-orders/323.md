# Work order #323 — Kotha: semantic RAG retrieval endpoint
> milestone: v26 — Kotha & adaptive · branch: `feat/issue-323`

## Goal
A /stories/search endpoint with embeddings so future tools can find similar learning moments.

## Done when
- [x] Embedding column
- [x] Top-K search
- [x] Privacy-scrubbed

## What shipped
- **Embedding column** — already the `story_embeddings` table from #329
  (`embedding vector(384)`, gte-small, unique story_id). This work adds the
  retrieval side.
- **Top-K search** — `POST /api/v1/admin/stories/search` (admin-gated, system
  capability): embeds the query with the same lazy gte-small encoder
  (`embed_text` helper in `embeddings.py`), then `ORDER BY
  embedding.cosine_distance(:q) LIMIT k` over `story_embeddings` (L2-normalized
  at encode time, so cosine ≈ the canonical `<=>` operator). `top_k` default 5,
  clamp 1–20; `query` 2–300 chars.
- **Privacy-scrubbed** — the response carries ZERO kid identity: only the
  story's context envelope (question / wrong answer / Moni's reason) plus
  skill, game, outcome, error kind, misconception code, action, and created_at.
  No `kid_id`, no names, no uids. Hits report `similarity` (1 − distance) and a
  scrubbed note. This matches the embed job's PII-safe text policy (#329).
- **Never crashes on a missing ML stack** — pgvector absent → `503` with a
  clear message; model absent (`embed_text` returns None) → `503`. Exactly the
  embed job's degradation philosophy, surfaced as an honest status instead of a
  stack trace.
- **Response schema** — `StorySearchIn / StorySearchHit / StorySearchOut`
  (pydantic, `response_model=StorySearchOut`).
