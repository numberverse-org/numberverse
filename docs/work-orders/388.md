# Work order #388 — API: schema drift — new model columns crash deployed DB (no migrations)
> milestone:  · branch: `feat/issue-388`

## Goal
`Base.metadata.create_all` creates missing TABLES but never alters an existing
table to add a new COLUMN — so a model change silently took the production API
down (`UndefinedColumn: column profiles.aggregate_opt_in does not exist` →
every auth call 502'd). Add an idempotent column-migration step.

## Done when
- [x] Idempotent migration step: new model columns auto-added to existing tables on boot
- [x] It never fails on a populated table (NOT NULL + no default handled safely)
- [x] A fresh deploy cannot take the API down due to a new column

## What shipped
- **`apps/api/app/migrations.py` — `apply_column_migrations()`**: after
  `create_tables()`, diffs every mapped table against `information_schema`
  (via the SQLAlchemy inspector) and issues `ALTER TABLE … ADD COLUMN IF NOT
  EXISTS` for any column the models declare that the DB lacks.
  - Type + server_default come straight from the model (`CreateColumn`
    renders `BOOLEAN DEFAULT 'false' NOT NULL`, `TIMESTAMP DEFAULT now()`, …).
  - A NOT NULL column with NO server_default is added NULLABLE (never fails on
    a populated table — the app treats None as the default).
  - Costs one inspector query + zero DDL when nothing changed; idempotent so it
    runs every boot safely.
- **Wired into `seed.py::create_tables()`** — runs right after create_all,
  before any route serves.
