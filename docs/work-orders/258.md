# #258 — Parent: per-kid voice preference

**Status:** ✅ Shipped (PR #572)
**Priority:** low · parent-facing

## Goal
Let parents choose which voice reads aloud per kid (gender/tone) and how fast, with a try-button.

## Done when
- [x] Voice + speed — "🗣️ Voice" block in Reading & sound: TONE chips (Warm adult · Kid · Soft female · Friendly male) + SPEED chips (Slower 0.8× · Normal 1.0× · Faster 1.2×)
- [x] Try-button — a real TTS sample plays with the selected tone+speed in the portal's own language (tone biases which installed Web-Speech voice wins; speed scales the rate)
- [x] Stored per kid — `KidSettings.voice_tone` (stable handle) + `voice_speed` (rate multiplier), nullable (null = the kid app's default warm-female at normal speed)

## What shipped

- `apps/parent/app/globals.css` — `.voice-pref`/`.vp-row`/`.vp-label`/`.vp-chips`

- `apps/kid/src/App.tsx` — settings effect applies `setVoiceTone(settings.voice_tone)` + `setVoiceSpeed(settings.voice_speed ?? 1)` alongside `setVoiceBalance`

## Design notes
- Tone → neural speaker id is the same 16-speaker model the kid app's own picker uses (warm-female = the default, id 11). A portal tone OVERRIDES the device-local picker; null = the device picker.
- Speed only scales the Web-Speech path (English + Bangla fallback) because the neural Piper model's tempo is baked in (length_scale 1.0). Caller overrides (math lines pass rate 0.9) still scale — the multiplier is applied on top.
- `voiceScore` reads `parentVoiceTone` (a `let` declared later in the module) at call time — safe (no TDZ read at module init).
