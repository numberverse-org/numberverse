# Work order #329 — Kotha: batch-embed stories to pgvector
> milestone: v26 — Kotha & adaptive · branch: `feat/issue-329`

## Goal
A server job that embeds new stories with gte-small and stores vectors for retrieval.

## Done when
- [x] Job idempotent
- [x] Uses pgvector
- [x] Runs on schedule

## What shipped
- **Idempotent job**: `embed_stories(db)` in `apps/api/app/embeddings.py` picks
  only stories WITHOUT a row in `story_embeddings` (unique `story_id`) and
  inserts with `ON CONFLICT (story_id) DO NOTHING` — re-running is always a
  no-op, and the summary reports `embedded` vs `pending`.
- **Uses pgvector**: new `story_embeddings` table — `embedding vector(384)`
  (gte-small), `model`, `dim`, FK→learning_stories. The Postgres `vector`
  extension is ensured best-effort at job time (`CREATE EXTENSION IF NOT
  EXISTS vector`). The model lives in its own module so the API boots even
  where `pgvector` is absent (degrades to `HAVE_VECTOR = False`).
- **Runs on schedule**: an asyncio background loop in the FastAPI lifespan
  fires every `kotha_embed_interval_minutes` (15), cancelled on shutdown, and
  `POST /api/v1/admin/stories/embed` triggers it manually. If the model/pgvector
  stack is missing the job reports `skipped` instead of crashing — once the
  stack is present it quietly catches up.
- **Opt-in heavy dep**: `pgvector>=0.3` is a base dep; the actual model
  (`sentence-transformers` → `thenlper/gte-small`) is the optional
  `numberverse-api[embeddings]` extra, loaded lazily. PII-safe text: only the
  story's context envelope (question / wrong answer / Moni's reason) + skill
  & game ids are embedded — never names, never kid ids.
