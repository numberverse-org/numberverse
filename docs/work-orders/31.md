# Work order #31 — feat: per-line neural WAV cache (IndexedDB LRU) + idle pre-synth of common phrases
> milestone: v14 — polish & perf · branch: `feat/issue-31`

## Acceptance criteria (from the issue)

**Why (kid-first):** the neural voice's *first-run* speed is fixed by #28 + the upcoming #29 (int4). But **every session** still pays a per-line synthesis cost: each spoken phrase runs phonemizer (~50–200ms) + ORT session inference (~100–500ms) on the WASM worker. The game repeats the same short phrases constantly (counting 1–10, `ঠিক আছে`, `নোট`, question stems) — so a per-text WAV cache makes the 2nd+ occurrence instant, and idle pre-synthesis makes the common ones instant from the very first line of a session.

**Acceptance criteria**
- [ ] **WAV LRU cache in IndexedDB** (`neuralVoice.ts`): key `"${speakerId}:${text}"` on the already-cleaned text → cached `Blob`. On hit, skip synth and play straight from cache; on miss, synth + store. Cap total bytes (~30MB) with LRU eviction by last-used. Survives reload (IndexedDB) → visit 2+ benefits too.
- [ ] **Idle pre-synthesis of common phrases:** after the model is ready, synthesize the top-N game phrases in small background batches (numbers 0–10, praise/repeat/prompt words, common question stems) so the first gameplay lines are already cached. Must be non-blocking and cheap.
- [ ] Respect queue/latest-wins semantics exactly (cache is keyed by text, so a cached line still goes through the existing token + playBlob path).
- [ ] **Measure:** in the parent-panel voice card, surface a privacy-safe local metric (localStorage, no network): synth-time hit vs miss. Show the hit rate after a normal session.
- [ ] `tsc --noEmit` clean · audit clean · oracle 35/35 CLEAN · CI green.

**Guardrails:** privacy stays the moat (cache is on-device, nothing leaves the device) · Web Speech fallback untouched · iOS audio-unlock untouched · no ads/analytics.
