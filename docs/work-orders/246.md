# Work Order #246 — Parent: multi-kid onboarding flow

**Status:** DONE · **PR:** #560 · **Branch:** feat/246-onboarding-flow · **Merge:** main

## Problem
A brand-new account (0 kids) landed on a bare dashboard with only a small hint
("No kids on this account yet — add one above.") and a tucked-away ＋ chip. No
guidance to set up the family, and no encouragement to add more than one kid.

## Fix
A guided first-run **onboarding wizard** opens the moment an account has no
kids, with a language toggle already in place (EN + বাংলা — the catalog is a
country-pack map, so a new locale is a new key, not a rewrite).

- **Guided steps** — 👋 welcome, pick an avatar, enter name + birth year, Add.
  Pressing Enter adds too. After each successful add the wizard STAYS open and
  shows the growing family as chips, so adding 2+ kids back-to-back is natural
  ("➕ Add another" keeps focus on the name field).
- **Finish / Not now** — once at least one kid exists the primary CTA becomes
  "🚀 Finish →" (into the dashboard); with 0 kids it reads "Not now". Finishing
  sets `nv_parent_onboarded` so the wizard never re-opens on this browser even
  if all kids are later deleted.
- **Editable later** — the wizard says so, and the normal dashboard keeps the
  ＋ Add-kid chip and the edit (rename/avatar/birth year) form. If onboarding is
  skipped with 0 kids, a "＋ Add your first kid" fast path opens the form.
- **Offline** — the wizard is fully client-side; on a failed save the parent's
  typed values are KEPT (no data loss) with a retry message, and after any
  successful create the dashboard re-fetches so nothing is stale. After the
  wizard, the whole dashboard works from already-loaded state (offline-friendly).
- **i18n-ready** — `WIZARD_LANGS` is `{ en: {...}, bn: {...} }`; add `"hi"`,
  `"ar"`, … with the same shape and the flow follows. Language picked via
  `nv_parent_lang` (localStorage) with a toggle in the card header.
