# #123 — Uptime monitor → Telegram alert

**Status:** 🔜 in progress (PR open)

## Problem

Nothing watched the live site. A broken deploy or a crashed container could
sit unnoticed until a user complained.

## Fix

New `infra/monitor/uptime_monitor.sh` + a 5-minute crontab job on the box:

- **Monitor loop on box** — every 5 min probes the live domain AND the origin
  (`http://192.168.0.104:8080`, bypassing Cloudflare). A healthy release is
  reachable at either, so tunnel/edge cache lag alone never counts as down.
- **Telegram alert fires** — Bot API `sendMessage` to the operator's own
  chat; **proven live**: `--test` sent from the box → `✓ test alert sent`.
  Credentials live in `~/.env.monitor` on the box (chmod 600, never in the
  repo — deploy.sh rsync excludes box-only env files anyway).
- **False-alarm guard** — alerts only after **3 consecutive failures**
  (≈15 min), once per episode (recovery message resets the counter). No
  alert storms; state persists across cron ticks in `~/.numberverse-monitor/`.

## Files
- `infra/monitor/uptime_monitor.sh` — probe + state machine + tg_send + `--test`

## Verification
- State machine: healthy tick → 3×simulated DOWN → threshold crossed → recovery ✓ (local, fake URLs)
- Box live tick: `ok (live=200 origin=200)` ✓
- Telegram: `--test` → `✓ test alert sent` ✓
- Crontab: `*/5 * * * * CRON=1 bash .../uptime_monitor.sh` ✓
