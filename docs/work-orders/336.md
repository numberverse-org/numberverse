# Work order #336 — Kotha: admin story health dashboard
> milestone: v26 — Kotha & adaptive · branch: `feat/issue-336`

## Goal
An admin view of story counts per kid/skill/error-kind with a sanity check.

## Done when
- [x] Counts + breakdown
- [x] Rate-limit aware
- [x] No kid PII in charts

## What shipped
- **`GET /api/v1/admin/stories/health`** (admin-only, registered BEFORE the
  `/{resource}` catch-all so react-admin never swallows it).
  - **Counts + breakdown**: total stories + chart buckets per skill, per Moni
    error kind (fatigue/misconception/gap/guessing/slip), per plan action, and
    a 14-day ingest trend — plus a top-10 per-kid histogram.
  - **Rate-limit aware**: a per-hour story budget (`STORY_RATE_LIMIT_PER_HOUR
    = 200`). Kids who crossed it in the last 60 min land in
    `high_velocity_kids` (kid id + last-hour count + over-budget delta) — a
    runaway sync loop or outbox replay is visible at a glance. The `sanity`
    block turns that into warnings (`ok: false`) and also flags an empty lake
    or a single kid owning the corpus.
  - **No kid PII in charts**: the per-kid chart is anonymous rank buckets
    (`Kid #1 … #10`), and skill/error/action/day charts carry zero kid data.
    The only kid-identifiable payload is `high_velocity_kids` — operational
    detail for an admin to act on, deliberately kept out of the charts.
