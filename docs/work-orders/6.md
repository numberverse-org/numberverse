# #6 — Playtime caps per weekday + gentle in-app enforcement

**Status:** 🚧 in progress (feature branch `feat/issue-6`)

## Problem

A single flat "Daily playtime" cap couldn't tell school nights (45 min) from
weekends (90 min). And the cap message was a flat notice — not Nova's voice.

## Acceptance (from the issue)

- [x] **Parent sets cap per weekday** — the parent portal's "Playtime per day"
      editor (Mon..Sun, chips Off/30/45/60/90) with "↺ Default (45/90)" and
      "No limit" presets.
- [x] **Default 45 min school, 90 weekend** — applied automatically when the
      parent has never configured caps (out of the box).
- [x] **At cap: Nova says "Wow, you played so much today! Come back tomorrow 💤"**
      — the kid-facing banner is now Nova-voiced (EN + BN).
- [x] **PLAY button soft-disables** — the existing gentle block, now driven by
      the effective per-weekday cap.
- [x] **EN + BN** — kid-facing text bilingual; portal English (existing).
- [x] **Audit clean** — all gates pass locally.

## Design

- **Data**: new `kid_settings.weekday_limits_min` column — a comma-joined 7-int
  string `"45,45,45,45,45,90,90"` (Mon..Sun; 0 = unlimited that day). Auto-added
  on existing DBs by the #388 column-migration boot path (no manual DDL).
- **Effective cap** (`todayLimitMin()` in the kid api): per-weekday array →
  flat `daily_limit_min` (legacy) → built-in defaults 45/90. `null`-safe.
- **Portal**: per-day chips write the 7-array; the display mirrors the kid's
  `todayLimitMin` so what the parent sees is what gets enforced.
- **Kid app**: `playLimitReached` now calls `todayLimitMin(settings)`; the
  blocking banner string is Nova's gentle line.
