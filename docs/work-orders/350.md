# #350 — Polish: reduced-motion mode

**Status:** in progress (2026-08-13)

## Problem

The app was dense with motion — confetti, screen shakes, bouncing mascots,
floating decor, pulsing buttons. For a kid who finds motion overwhelming (or a
device whose OS already requests reduced motion) there was no way to calm it.

## Fix

A two-source reduced-motion system, plus JS-side gating:

- **`apps/kid/src/game/reducedMotion.ts`** (new) — `prefersReducedMotion()` and
  `setReducedMotion()`. Priority: in-app toggle (`nv_reduced_motion`) > OS
  `prefers-reduced-motion` > motion on.
- **CSS** (`styles.css`) — blanket override killing non-essential animation +
  transition under `@media (prefers-reduced-motion: reduce)` AND under
  `html.nv-reduce-motion` (the in-app toggle).
- **Settings** (App.tsx) — a "Reduce motion" 🦋 switch in the Screen section
  (same `.switch` style as Fullscreen); toggling sets
  `documentElement.nv-reduce-motion` + persists. New `settingsReduceMotion` i18n
  (EN "Reduce motion" / BN "কম গতি").
- **Canvas** — `confettiBurst`/`starBurst` (celebrate.ts) and the wrong-answer
  shake (feedback.ts) early-return via `prefersReducedMotion()`, so the Phaser
  tweens honour it too (the floating text + chime still fire).

## Files
- `apps/kid/src/game/reducedMotion.ts` — new helper
- `apps/kid/src/game/celebrate.ts` — gate confetti/star bursts
- `apps/kid/src/game/feedback.ts` — gate wrong-tap shake
- `apps/kid/src/App.tsx` — Settings toggle + `settingsReduceMotion` i18n
- `apps/kid/src/styles.css` — media-query + class blanket overrides
