# Work Order #247 — Parent: PIN recovery flow (security Q&A)

**Status:** DONE · **PR:** #561 · **Branch:** feat/247-pin-recovery · **Merge:** main

## Problem
The 4-digit parent-area PIN (#86) had no proper recovery: a forgotten PIN (or
the 3-try pad lock) could only be reset by signing out and back in — which
needed the parent's account credentials and interrupted the session.

## Fix
A per-device **security-question recovery** that resets a forgotten PIN **in
place — offline, no sign-out, no account lockout**.

- **Set Q&A at first use** — right after the first-time PIN setup confirms, the
  flow steps straight into "Pick a recovery question → answer → confirm" (pick
  from a fixed i18n list, index stored so a locale change never corrupts it).
  Skippable; the panel's new **"PIN recovery question" card** sets/changes it
  anytime (shown alongside the existing Change-PIN card).
- **Recovery works offline** — Q&A lives in localStorage (salted FNV-1a hash of
  the answer, never the raw answer), same per-device trust model as the PIN.
  On the unlock/locked pad, "Forgot PIN?" now opens the question + answer; a
  correct answer clears the PIN and drops straight into setting a new one.
  Answers are normalized (trim / lower-case / collapse spaces) so "Blue " and
  "blue" both verify.
- **No account lockout** — wrong PINs only ever lock the pad (never the
  account), and with Q&A set the parent resets in place; without Q&A the
  two-tap sign-out reset remains as the fallback, so there is always a path.
  A wrong Q&A answer just shows "try again" — nobody gets locked out.
- **i18n-ready** — questions + all strings added to the EN + বাংলা locale
  objects (country-pack seam unchanged).
