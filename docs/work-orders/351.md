# #351 — Polish: keyboard navigation for parent area

**Status:** ✅ released in 0.26.12 (2026-08-13)

## Problem

The parent area (kid app parent panel + the parent portal) had no visible focus
indication for keyboard users and the kid-switcher chips didn't follow the ARIA
tablist keyboard pattern.

## Fix

- **Focus visible (both apps)** — a `:focus-visible` outline (#4cc9f0 in the kid
  app, #7de3ff in the portal) so keyboard users always see where they are while
  mouse/touch taps never show a ring (kids aren't distracted). The ring follows
  each element's own `border-radius` (pills stay pill-shaped). Inputs keep their
  border change AND gain a focus-visible ring (their `outline: none` no longer
  hides the keyboard ring).
- **Tab order — kid switcher** (`parent-picker` `role="tablist"`) is now a real
  ARIA tablist: roving `tabIndex` (only the selected chip is tabbable) and
  `←/→` + `↑/↓` + `Home/End` move focus AND selection. `parentChipRefs` Map
  focuses the newly-selected chip.
- All parent-area controls (sign-out, portal door, chips, portal buttons/links/
  inputs) were already native `<button>`/`<a>`/`<input>` elements, so Tab order
  and Enter activation work natively — this issue closed the visibility gap and
  made the switcher pattern correct.

## Files
- `apps/kid/src/styles.css` — global `:focus-visible` ring + input ring
- `apps/kid/src/App.tsx` — roving tabindex + arrow-key nav on the kid switcher
- `apps/parent/app/globals.css` — portal `:focus-visible` ring + input ring
