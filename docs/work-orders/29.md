# Work order #29 — tech: int4 model cut needs an ORT upgrade (blocked on onnxruntime 1.17 — see #28)
> milestone: v14 — polish & perf · branch: `feat/issue-29`

## Acceptance criteria (from the issue)

**Follow-up to #28** — int4 model cut. Blocked on ORT 1.17 (proven); **feasible on ORT 1.27 (proven)**.

**PROVEN 2026-08-11 (not guessed):** I downloaded `onnxruntime-web@1.27.0` and inspected its WASM binary. It contains the full int4 kernel family:
- `INT4` / `UINT4` tensor types (in the type enum)
- `ApplyMatMulNBits`, `DirectDQFusedMatMulNBits`, `DQMatMulNBitsFusion`, `DP4AMatMulNBits`, `DQMatMulToMatMulNBits`
- `Explicit qdq_matmulnbits_block_size must be a power-of-2` (block-wise int4 QDQ) + `GetPackedUint4Element`
- `DequantizeLinear` opset versions 10/13/19/21/23/24/25 (the opset-21 int4 path is there)
By contrast, the pinned **1.17.0** WASM had **zero** int4 symbols — that's why int4 was blocked. The path forward is a **clean swap of the ORT bundle only** (piper-wasm 0.1.4 worker + phonemizer stay; just replace `ort.min.js` + the `.wasm` files with 1.27.0 equivalents and keep `numThreads=1`).

**Goal:** Bangla model ~20MB int8 → ~10MB int4 → cold first-run `neural.ready` ~4–5s total (was ~6–7s after #28's gzip).

**Acceptance criteria**
- [ ] **Swap ORT bundle → 1.27.0** in `infra/deploy/scripts/fetch_voice_assets.sh` (keep the single-thread patch — `numThreads=1`, no COOP/COEP). Verify the worker still initializes + synths with 1.27 (the file naming changed — plain `ort-wasm-simd.wasm` must be the single-thread build the loader picks with `numThreads=1`).
- [ ] **int4 weight-only QDQ** in `quantize_voice.py` (per-channel block, symmetric, packed int4 initializers + DequantizeLinear with `block_size`, opset ≥21). Keep int8 as the default path; make int4 an explicit mode.
- [ ] **Verify the int4 model RUNS** through onnxruntime 1.27 end-to-end (load + synth one sentence in Node/python 1.27 on the box — shares the WASM kernel implementation).
- [ ] **Ship int8 by default; int4 as an opt-in build (QA artifact).** The PR must NOT put a possibly-degraded voice live before a human listens.
- [ ] **Listen-QA (human gate):** on the 4 parent-panel voices (female 11 / kid 12 / soft 3 / warm 7) vs the int8 build, on a real device. Don't merge the int4 flip on benchmarks alone.
- [ ] Measure cold-cache first-run before/after on nominal 4G (parent-panel voice card + curl on the box).
- [ ] `VOICE_V` bump; Web Speech fallback + iOS gesture-unlock untouched.
- [ ] Also verify `/voice/*` is actually edge-cached by Cloudflare (immutable headers set — confirm tunnel serves from edge, not origin round-trip) + HTTP/3 reachable.

**Guardrails:** privacy stays the moat (on-device, edge = static CDN only) · Web Speech fallback so Bangla is never silent · iOS audio-unlock untouched · no CDP headless Chrome for testing (verify live on the box + a real phone).
