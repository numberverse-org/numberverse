# #303 — Ops: container log cleanup

**Status:** ✅ done (merged — issue CLOSED)

## Problem

Docker containers wrote unbounded json-file logs to box disk — no rotation, no
size cap, nothing tying logs to a cleanup schedule.

## Done-when (from the issue)

- [x] **Rotation set** — docker's `json-file` driver now rotates each service's
      logs automatically (compose `x-logging` anchor on every service).
- [x] **Size cap** — `max-size: "10m"` / `max-file: "3"` per container = max
      30MB per service, oldest dropped first.
- [x] **Part of clean-logs** — docker's built-in rotation IS the cleanup
      mechanism (no separate cron needed on the box).

## Files

- `infra/deploy/docker-compose.prod.yml` — `x-logging` anchor + per-service
  `logging` (postgres, api, web)
- `infra/docker-compose.yml` — same for dev (postgres, redis)

## Verification

- Both compose files parse (`yaml.safe_load`) with `logging` present on all 5
  services ✓
