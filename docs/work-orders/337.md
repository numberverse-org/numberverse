> milestone: v26 — Kotha & adaptive · branch: `feat/issue-337`

## Goal
Rotate question framing/presentation to reduce repetition fatigue.

## Done when
- [x] ≥3 framings per skill
- [x] Seamless swap
- [x] i18n clean

## What shipped
- **`framing.ts`**: a shared FRAME_BANK + `frameText(baseKey, skillId, round,
  vars)`. Each round picks a variant DETERMINISTICALLY from
  `hash(skillId) + round`, so a kid never sees the same phrasing twice in a
  row, the SAME skill+round always gives the SAME variant (no jitter), and
  un-framed keys degrade gracefully to the original copy.
- **5 question types × 3 framings each**, i18n'd EN + BN:
  - `howManyFruit` (FruitAdd add) — "How many fruit in all?" / "Count every
    fruit…" / "All the fruit together makes…"
  - `howManyInAll` (FruitAdd story) — 3 variants
  - `howManyMore` (NumberBonds make-10) — 3 variants
  - `roundTap` (Count & Pop) — 3 variants
  - `count100Round` (Count to 100 rods) — 3 variants
- **Wired into the 4 highest-played drill scenes**: CountPop, Count100,
  FruitAdd (per add/sub seed), NumberBonds (reframed each round).
- **i18n clean**: variants are lazy t() references → audit sees them used, no
  drift, and each exists in EN + BN.
