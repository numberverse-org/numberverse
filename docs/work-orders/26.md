# Work order #26 — Game doesn't speak until 'Listen' button is tapped first
> milestone:  · branch: `feat/issue-26`

## Acceptance criteria (from the issue)

## Bug
On a fresh app load, the game is SILENT — no question is spoken. Speech only starts working after the user taps the 🔊 Listen/replay button once, then every later line speaks.

## Expected
The first question should speak automatically on round start (no manual Listen tap needed).

## Why high priority
Audio-unlock: on iOS/PWA the FIRST `speak()` must run synchronously inside a user gesture. If the game's first question is spoken from a deferred context (scene start / timer), the engine never unlocks and stays mute until a real gesture taps Listen. This is the iOS-strictest case — but the app should never need a manual unlock.

## Acceptance
- [ ] First round speaks on its own — no Listen tap required
- [ ] Works on iOS PWA (strictest) and Android
- [ ] Bangla (neural) AND English (Web Speech) both auto-speak
- [ ] audit clean, typecheck clean, oracle CLEAN
