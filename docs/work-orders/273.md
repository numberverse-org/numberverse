# #273 — Privacy: data export for parents

**Status:** ✅ done (merged PR #432 — issue CLOSED)

## Problem

A parent had no way to download their own family's learning data from the API
in a readable form — it lived behind scattered endpoints (mastery, stories,
activity) with no single, portable view.

## Done-when (from the issue)

- [x] **Export endpoint** — `GET /api/v1/export` returns a versioned, readable
      JSON document with the whole family: profile identity, each kid's
      profile/settings, mastery rows, every progress event, and every learning
      story. `GET /api/v1/export.csv` gives the round history as one
      spreadsheet-ready row per round (kid name resolved, UTF-8 BOM so Bangla
      names survive Excel).
- [x] **CSV/JSON** — both formats shipped (above).
- [x] **Auth-protected** — both routes use `get_current_profile` (valid,
      unrevoked session token) and scope queries to `profile_id` — a parent
      can only ever export their OWN kids. Response is an attachment download.
- [x] **No account internals** — the payload deliberately omits
      `password_hash`, session/token material, and `is_admin`. Enforced by a
      CI unit test.

## Design

- `apps/api/app/export_format.py` — pure, dependency-free serializers
  (duck-typed, no sqlalchemy/fastapi imports) so the format is unit-testable
  in CI with zero Postgres, same pattern as `bandlock.py`. Includes the
  privacy contract (`profile_meta`), the versioned kid serializer
  (`serialize_kid`), and the CSV builders (`round_rows`, `to_csv`).
- `apps/api/app/routers/export.py` — thin router: four batched `IN` queries
  (settings/mastery/events/stories by owned kid ids) → pure serializers →
  download response with `Content-Disposition`.
- Naive Postgres TIMESTAMPs serialize as UTC ISO `…Z` so a parent opening the
  file in any tool sees unambiguous times.
- Mastery is clamped 0..1 in the export (matches what the client shows).
