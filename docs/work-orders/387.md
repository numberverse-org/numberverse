# Work order #387 — Voice: Bangla still reads as latin when no Bangla voice is installed
> milestone:  · branch: `feat/issue-387`

## Goal
On a device with NO Bangla TTS voice, Bangla lines were read by the engine's
default (English) voice → "speaks like latin, not bengali". Stop it.

## Done when
- [x] Bangla text is NEVER read by a non-Bangla voice
- [x] The on-device neural voice is the reliable Bangla path on voice-less devices
- [x] English speech is unaffected

## What shipped
- **`webSpeak()` guards the wrong-language fallback** (`apps/kid/src/game/
  speech.ts`): when `pickVoice("bn")` finds NO Bangla voice on the device, the
  Bengali line is now DROPPED (silent) instead of handed to the engine's
  default voice — which read Bengali script as latin gibberish. This was worst
  on the neural voice's download window (first visit, ~20MB), when EVERY Bangla
  line fell back to Web Speech on devices without a bn TTS pack (desktop
  Chrome, phones without Google বাংলা).
- The on-device Piper neural voice remains the primary Bangla path — it
  preloads at boot and retries on every gesture, so a voice-less device goes
  silent-for-Bangla for only the download window, then speaks proper Bengali.
  On devices WITH a Bangla voice (Google বাংলা / Apple), webSpeak still works
  immediately, and the #381 normalizer makes that voice read clean Bangla too.
- English is untouched (it never hits the guard).
