# #93 — Kid-safe share images: strip kid name/photo metadata

**Status:** 🔜 in progress (PR open)

## Problem

Share cards are canvas-generated PNGs (no camera EXIF), but the PNG format can
carry `tEXt`/`zTXt`/`iTXt`/`eXIf` metadata chunks (Software, Comment, Source)
that a future renderer/library could fill with a kid's name or a filesystem
path. Nothing guaranteed a share PNG was metadata-free before it hit WhatsApp.

## Fix

Byte-level PNG metadata stripper + a proving test:

- **`packages/core/src/png.ts`** — `stripPngMetadata()` rebuilds a PNG keeping
  ONLY the pixel-critical chunks (`IHDR`/`PLTE`/`tRNS`/`IDAT`/`IEND`), dropping
  every metadata chunk. Pure, deterministic, dependency-free (browser + Node).
  Non-PNG input passes through unchanged (never corrupts).
- **`apps/kid/src/game/shareImage.ts`** — `canvasToBlob()` now runs the blob
  through `stripPngMetadata` before it's shared/downloaded.
- **`scripts/test-png-metadata.mjs`** — self-contained: builds a valid 1×1
  PNG, injects `tEXt` chunks with a kid name, a filesystem path, a phone, and
  a software tag (correct CRC32), then proves the stripper removes them all
  and the output is byte-identical to the original clean PNG. Non-PNG passthrough
  also checked.
- **CI** — the `audit` job (which already has `@numberverse/core` built via
  the `core-dist` artifact) now runs the PNG test too.
