# #91 — Safety: automated content scan as a CI gate

**Status:** 🔜 in progress (PR open)

## Problem

The Oracle's `l1_safety()` check ran in the standup but had **no allowlist**
and its output was opaque (a hit just made "oracle gate CLEAN" go red). A new
scene could ship an unsafe word with the specific file/word invisible to the
contributor, and there was no sanctioned path for a legitimate collision.

## Fix

New `scripts/content-safety.mjs` + `content-safety` CI job:

- Scans every skill title (`packages/core/src/skills.ts`) and every quoted
  display string in `apps/kid/src/game/*Scene.ts` against the word-boundary
  unsafe list (`kill`, `blood`, `bomb`, `weapon`, `ghost`, `demon`, `dead`,
  `stupid`, `liar`, `die`, `gun`, …). `skills` never trips `kill`.
- **ALLOWLIST** map (word → required reason) for legitimate kid-safe
  collisions — the Oracle lacks this.
- Fail-closed, **clear error** names file:line + word.
- `docs/CONTENT_SAFETY.md` — how to add to the allowlist, why it mirrors the
  Oracle's `l1_safety()`.

## Files
- `scripts/content-safety.mjs` — new gate
- `docs/CONTENT_SAFETY.md` — allowlist + no-ads policy (shared with #92)
- `.github/workflows/ci.yml` — `content-safety` job
- `docs/RELEASING.md` — gate table row

## Verification
- Clean tree: "✓ no unsafe words in shipped content" (54 titles + 42 scenes) ✓
- Fail-closed: planted `"this weapon kills kids"` → both flagged, exit 1 ✓
