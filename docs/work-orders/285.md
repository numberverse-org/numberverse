# #285 — Custom avatar builder

**Status:** ✅ done (PR pending → issue CLOSE)

## Problem

Kids can only pick from preset buddy avatars. Acceptance: **6+ parts each** ·
**persisted per kid** · **offline**.

## Fix

A 🎨 **Build Your Buddy** mixer in the home "More ▾" menu: pick a base face
(the existing preset buddies) then layer **Hat/Hair**, **Eyes** and **Clothes**
from 7 options each (incl. "none"). The composite preview updates live, and the
look is saved per kid — offline, in `localStorage`.

- **Parts** (`App.tsx`) — `AvatarParts { base, hat, glasses, outfit }` with
  `AVATAR_PART_OPTIONS` (7 choices each for hat/glasses/outfit incl. "none") and
  `AVATAR_PART_LABELS`. `Kid.avatarParts?` is optional so existing kids fall
  back to their plain avatar.
- **Renderer** — `KidAvatar` composites the base emoji under absolutely-layered
  `.ap-hat` / `.ap-glasses` / `.ap-outfit` emoji layers. Used in the kid-picker,
  home journey node and the builder preview.
- **Builder UI** — `AvatarBuilder` screen with live `.avatar-preview`, a Face
  base row (all presets) and one part-row per category; the Save button persists
  via `updateKidAvatar` (updates kid + `nv_kids` localStorage + the selected-kid
  cache).
- **i18n** — 10 new `Strings` entries EN + BN (`avatarTile/Title/Sub/Preview/
  Face/PartsLabels/None/Save/SaveSpeak`) — locale-pack ready for any country.
- **CSS** — `.avatar-parts` + `.ap-*` layering, `.avatar-screen`, `.avatar-
  preview`, `.avatar-part`, `.avatar-part-row`, `.avatar-save`.
- **Offline** — pure localStorage; no network.

## Files
- `apps/kid/src/App.tsx` — parts config, `KidAvatar`, `AvatarBuilder`, screen
  routing, More-menu tile, Strings EN+BN
