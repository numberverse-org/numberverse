# #9 — Multi-device profile sync via optional parent account

**Status:** ✅ done (PR pending → issue CLOSE)

## Problem

One kid profile should follow them across a phone + tablet. Families with two
devices reset progress today because each device keeps its own local store.
The issue's acceptance: **opt-in sync; conflict resolution = newest-wins;
offline-first unaffected; privacy = only aggregate mastery + coins (no
voice/face).**

## What already existed

The app already had the UPLOAD half: a durable outbox (`pending`) drains every
round to `POST /progress`, kids map to server kids under a parent account
(`mapLocalKidsToServer`), and the server accumulates per-skill mastery. What
was missing was the DOWNLOAD half: a second device never pulled that server
state back, so it started empty.

## Fix

Closed the loop with a **restore side**, E2E-friendly by construction:

- **Server** (`models.py`, `schemas.py`, `routers/progress.py`):
  - `Kid.coins` column (int, `server_default 0` — auto-migrated on boot by the
    existing migrations.py drift protection, so a populated DB gains it safely).
  - `POST /progress` now accepts an optional `coins: {kid_id: int}` map and
    keeps the **max ever reported** (newest-wins wallet).
  - New `GET /kids/{kid_id}/snapshot` → `{ kid_id, name, avatar, coins,
    mastery: [skill, mastery, correct, attempts, streak] }` — the aggregate
    profile a second device restores. **No voice, no face, no raw answers.**
- **Client** (`store.ts`, `api.ts`, `App.tsx`):
  - `store.restoreSnapshot(kidId, snap)` — newest-wins merge: a skill is taken
    from the server when it has **more accumulated corrects** than the local
    record (a device that just played and hasn't drained keeps its local value
    until the next outbox drain catches the server up); the wallet takes
    `max(local, server)`.
  - `api.fetchSnapshot` + `restoreServerState` — iterates mapped kids, pulls
    snapshots, merges. Runs on the auto-sync heartbeat (throttled to once/5min
    and NOT consumed while offline), and fires **immediately after a fresh
    parent sign-in** (`signinParent` / `signinGoogle`) so the tablet catches up
    the moment the parent lands.
  - `syncProgress` now sends each kid's current coin balance with every batch.
- **Opt-in by design** — device-only installs keep their private per-device
  account (unchanged). The profile follows only when the **parent signs in** on
  both devices, which is exactly the "optional signed-in sync" the issue asks
  for. Offline-first is untouched: restore never touches the outbox and never
  blocks gameplay.

## Files
- `apps/api/app/models.py` — `Kid.coins` (auto-migrated)
- `apps/api/app/schemas.py` — `ProgressBatchIn.coins`, `KidSnapshotOut`
- `apps/api/app/routers/progress.py` — coins upsert in `/progress`,
  `GET /kids/{kid_id}/snapshot`
- `apps/kid/src/store.ts` — `restoreSnapshot` (newest-wins merge)
- `apps/kid/src/api.ts` — coins on the batch, `fetchSnapshot`,
  `restoreServerState` (throttled heartbeat + online-event)
- `apps/kid/src/App.tsx` — restore on parent sign-in (password + Google)
