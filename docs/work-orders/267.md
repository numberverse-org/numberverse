# #267 — Safety: scheme/link allowlist

**Status:** ✅ released in 0.26.13 (2026-08-13)

## Problem

The apps had exactly two external-link sites — the kid app's WhatsApp share
fallback (`window.open` in shareImage.ts) and the parent portal's "Share on
WhatsApp" button — but nothing governed which schemes could ever be opened.
A future `href`/`window.open` with a custom scheme (e.g. `tel:`, `itms:`,
`intent:`) would just fire.

## Fix

Single allowlist in `packages/core/src/links.ts` (new), exported via core:

- `ALLOWED_EXTERNAL_SCHEMES` — only `https:`, `mailto:`, `blob:`, `data:`,
  `about:`. WhatsApp share is `https://wa.me` so it's already covered.
- `isAllowedExternalUrl(url)` — scheme check (relative URLs resolve against a
  dummy base, so internal links stay safe).
- `openExternal(url, target)` — opens ONLY if allowlisted, else no-op
  (used by the kid app's shareImage.ts fallback).
- `isWhatsAppShare(url)` — explicit wa.me check for the portal button.

Wired into:
- `apps/kid/src/game/shareImage.ts` — `window.open` → `openExternal`
- `apps/parent/app/page.tsx` — Share-on-WhatsApp `onClick` guard
  (`preventDefault` when the href is outside the allowlist).

## Files
- `packages/core/src/links.ts` — new allowlist + helpers
- `packages/core/src/index.ts` — export
- `apps/kid/src/game/shareImage.ts` — use `openExternal`
- `apps/parent/app/page.tsx` — click-guard the share link
