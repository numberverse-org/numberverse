# Work order #393 — Fix literal "Round {n}" placeholders in Count & Pop / Count to 100
> milestone: bangla-ux-wave · branch: `feat/issue-393`

## Acceptance criteria (from the issue)
- [x] Count & Pop round header reads "Round 3 · tap 5 numbers" (no literal braces)
- [x] Count to 100 round header reads "Round 2 · make 45" (no literal braces)
- [x] Bangla variants interpolate too (রাউন্ড ৩ …)
- [x] tsc, i18n audit, build all green

## Goal
The round header (the first thing a kid reads each round) was rendering the raw
i18n template `Round {n}` instead of "Round 1", "Round 2", … on prod.

## Root cause
`frameText()` picks a phrasing variant from `FRAME_BANK` via a lazy arrow
`() => t("roundTap1")` and calls it with **no vars**. `t()` only interpolates
placeholders when vars are passed, so the returned string kept its literal
`{n}` / `{count}` / `{target}` braces. The round vars reached only the fallback
path (`t(baseKey, vars)`), never the chosen variant.

Affected headers:
- `CountPopScene` → `t("roundTap1/2/3")` = "Round {n} · tap {count} numbers"
- `Count100Scene` → `t("count100Round1/2/3")` = "Round {n} · make {target}"

## What shipped
- **`apps/kid/src/game/framing.ts`** — every `FRAME_BANK` arrow now accepts the
  round's `vars` and forwards them into `t(variantKey, vars)`; `frameText()`
  calls `pick(vars)`. Variant keys stay visible as `t("roundTap1")` etc. so the
  i18n audit still counts them as used (no drift).
- Verified in the built bundle: the variant arrow compiles to
  `A => t("roundTap2", A)` (vars flow through) and there are no bare
  no-vars `t("roundTap…")` calls left.

## Notes
- Same-family headers checked: `build999Round` and plain `t("round", {n})`
  already pass vars correctly — only the framed variants were broken.
- The other flagged call sites (greatSinging/answerIs/findLetter/watchShare/
  regroupWin) are false positives: they pass vars via shorthand `{ name }`.
