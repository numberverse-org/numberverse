# #409 — UI/UX polish: no live demo creds on prod login, portal session spinner, localized Back labels

**Status:** ✅ released in 0.26.11 (2026-08-13)

## Problem

Oracle standup is 35/35 clean (palette, contrast, glyphs, assets, theme wiring
all green), but a hands-on UI/UX pass found three real issues the automated
checks don't see:

1. **Production parent-portal login publishes live demo credentials.**
   `apps/parent/app/login/page.tsx` rendered `Demo parent: demo@numberverse.dev /
   demo1234` unconditionally. That is a REAL seeded account (seed.py:144 — a live
   kid "Aria" + active plus subscription). On production the form advertised
   working credentials anyone could use — a security smell and confusing UX
   ("is this a real login?").
2. **Portal session-checking state looked frozen.** The new auth gate shows bare
   "Checking your session…" text while the token validates server-side; a slow
   API reads as a hang.
3. **10 back buttons hardcode `aria-label="Back"` (English).** In Bangla mode a
   screen reader announces English "Back" on 10 `icon-btn` back arrows.

## Fix

### 1. Demo credentials are demo-mode-only
- `apps/parent/app/login/page.tsx` — the hint renders only when
  `NEXT_PUBLIC_DEMO_MODE === "1"` (build-time). Default is OFF.
- `infra/deploy/Dockerfile.web` — new `ARG NEXT_PUBLIC_DEMO_MODE` /
  `ENV NEXT_PUBLIC_DEMO_MODE=${NEXT_PUBLIC_DEMO_MODE:-}` (safe production default).
- Verified: default build renders ZERO creds in `out/login.html`; a
  `NEXT_PUBLIC_DEMO_MODE=1` build renders them.

### 2. Session-checking spinner
- `apps/parent/app/globals.css` — `.spinner` (16px ring, cyan top, `nv-spin`
  0.8s) + keyframes.
- `apps/parent/app/page.tsx` — `<span className="spinner" aria-hidden />` before
  the checking text.

### 3. Localized back labels
- `apps/kid/src/App.tsx` — new `back` key in the `Strings` interface + EN
  ("Back") + BN ("ফিরে যাও").
- All 10 `aria-label="Back"` → `aria-label={t.back}` (settings, parent page,
  worlds, cert, done, castle, cards, etc.).

## Files
