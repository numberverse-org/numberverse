# #310 — Ops: backup encryption at rest

**Status:** ✅ done (merged — issue CLOSED; box armed)

## Problem

Nightly `pg_dump` → gzip dumps sat in plaintext on box disk (`~/backups/numberverse/pg/*.sql.gz`). Anyone with box access could read every kid's data.

## Done-when (from the issue)

- [x] **Encryption at rest** — every dump is now AES-256-CBC (openssl, pbkdf2,
      salted) → `*.sql.gz.enc`; plaintext never hits disk (dump → gzip → enc in
      one pipe, the `.sql.gz` intermediate is removed).
- [x] **Key stored safely** — key at `~/backups/numberverse/.backup_key`
      (600 perms, owner-only), OUTSIDE the dumps dir, path overridable via
      `PG_BACKUP_KEY`. Script FAILS LOUDLY (never auto-creates) if the key is
      missing — a silent auto-key would mint un-restorable backups.
- [x] **Restore still works** — `--drill` decrypts before restore; proven on the
      box for the new `.enc` format AND the legacy plain `.sql.gz` (backward
      compat). Both: `live=12 drill=12 ✓`.

## Files

- `infra/backup/pg_backup.sh` — key guard, encrypt-on-write, round-trip
  integrity check (decrypt→`gzip -t`), `decrypt()` handling both formats,
  drill on newest dump of either format.
