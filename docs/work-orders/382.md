# Work order #382 — Auth: Google sign-in is flaky (fails most of the time)
> milestone:  · branch: `feat/issue-382`

## Goal
The "Continue with Google" button on the parent gate disappears or 501s too
often. Make it robust: retry loading, hide it when the backend can't verify
tokens, and always leave a clear email path.

## Done when
- [x] GSI script load retries with backoff
- [x] Button hidden when backend isn't configured
- [x] Clear fallback error path

## What shipped
- **GSI script retry with exponential backoff** (`apps/kid/src/components/
  GoogleSignIn.tsx`): a fresh `<script src="…/gsi/client">` per attempt, up to
  3 attempts with 1s → 3s → 9s backoff, before the button gives up. On a flaky
  mobile connection one load attempt was often all it got.
- **Backend coherence check**: new public endpoint `GET /auth/google/status`
  (`apps/api/app/routers/auth.py`) returns `{ enabled: bool }` from
  `settings.google_client_id`. GoogleSignIn fetches it on mount and replaces
  the button with a friendly note when THIS server has no OAuth client — a
  build baked with `VITE_GOOGLE_CLIENT_ID` but a backend without
  `NV_GOOGLE_CLIENT_ID` used to show a button that 501'd on every tap.
- **Clear fallback path**: on failure the component renders
  `fallbackText` (`t.gateGoogleGone`, EN + BN added in App.tsx) in place of
  the button — "email below works too" — so the parent always lands on a
  working path. Email + guest remain the permanent fallbacks.
