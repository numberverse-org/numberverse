## What shipped

Switching the active kid **never loses the current session or mid-game state** —
switch away mid-lesson, switch back, and the app resumes exactly where the kid
left off.

### Kid app (`apps/kid`)
- **Per-kid session snapshot** — `savedSessionsRef` keeps an abandoned mid-flight
  session (`steps` + `sessionIdx` + `roundsDone`) keyed by the kid it was left
  behind for.
- **`snapshotSession(kidId)`** — snapshots the ACTIVE kid's in-flight session
  (only when actually mid-play). Triggered by:
  - the play-screen kid chip (before it navigates to the picker), and
  - `switchKidPreserving()` — the kid-pick switcher, which then selects the new
    kid and returns home.
- **`resumeSession(saved)`** — restores steps/idx/rounds, binds the stop's world
  + music, and jumps straight back into play. The home Play button checks for a
  saved session FIRST, so "Play" = resume, not restart.
- **Lifecycle hygiene** — a saved session is cleared the moment the session
  actually completes (`done`/`break`), and when the kid explicitly starts a NEW
  session (single skill or world sweep). No stale resumes.

### No double-sync
- Rounds already played stay in the durable `pending` outbox; resuming adds NEW
  rounds and syncs by uid (server dedup makes replays no-ops). `recordSession`
  still fires exactly once, on real completion — an abandoned session is never
  double-counted (it wasn't completed).

### Co-op intact
- The sibling pass-the-device flow still calls `selectKid` directly (NOT the
  preserving switcher) — intentional mid-session handoff, unchanged.

## i18n
- No new UI strings — the resume is invisible (the home Play button just
  resumes), so no locale work was needed beyond the existing strings.
