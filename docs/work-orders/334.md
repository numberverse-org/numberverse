# Work order #334 — Kotha: offline story queue quota
> milestone: v26 — Kotha & adaptive · branch: `feat/issue-334`

## Goal
Guard the on-device story queue size so a long offline stretch can't balloon storage.

## Done when
- [x] Cap + drain
- [x] No data loss before drain
- [x] Visible count

## What shipped
- **Cap**: `STORY_QUEUE_CAP = 300` (store.ts). The queue is a high-water mark,
  not a deletion threshold.
- **Drain**: `drainStoriesIfFull()` (api.ts) fires `syncStories()` the moment
  the queue hits the cap (App effect watches `stories.length`). Best-effort —
  if offline, the sync heartbeat keeps retrying.
- **No data loss before drain**: the cap never deletes. Stories are only
  removed by `clearStories()` AFTER the server confirms the batch (existing
  durable-outbox contract). Nothing is dropped before a confirmed send.
- **Visible count**: the sync pill now shows `📚 N` (the story backlog) next to
  the sync state, its tooltip lists `N rounds · N stories`, and when ≥20
  stories are queued a `storyQueueNote` banner explains they're saved on-device
  and will sync online (EN + BN).
