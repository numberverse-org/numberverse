# #94 — Encrypted sync payloads (design decision)

**Status:** ✅ done (merged — issue CLOSED; decision documented)

## Decision

Sync payloads are NOT encrypted end-to-end with a parent-held key. Recorded in
`docs/ENCRYPTED_SYNC.md` with full rationale.

## Why

The parent portal must read this data server-side to render progress, weekly
reports, wrong-answer history and the data export (#273). E2E with a
parent-held key would blind the portal to its own data. Device and portal are
the same privacy boundary (both the parent's own property), so transport TLS +
scoped per-account API + on-device/on-box storage is the right model. Documented
revisit trigger: if hosting ever becomes multi-tenant/external.
