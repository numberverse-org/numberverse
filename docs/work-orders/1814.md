# Work order #1814 — Persisted store blob is JSON.stringified on the main thread on every debounced write
> milestone: v39 — deepthink sweep · branch: `feat/issue-1814`

## Acceptance criteria (from the issue)

## Where
apps/kid/src/store.ts:701

## Why it matters
The trailing-edge persist writer hands the whole snapshot to createJSONStorage's setItem, which runs JSON.stringify over the entire persisted blob (skills + mistakes + stories up to STORY_HARD_CAP=600 + pending + accel + moni) synchronously on the main thread. The code's own comment (store.ts:661-665) measures this at ~10-70ms per write, and during active play the 150ms debounce keeps firing, so each burst of wrong-tap/round-reward set()s produces a multi-frame main-thread stall on the low-end Android devices this PWA targets.

## Suggested fix
Move the serialization off the main thread: postMessage the partialized snapshot (structured-cloneable) to a small dedicated worker that runs JSON.stringify and posts the string back; the main thread then does only the (unavoidable) localStorage.setItem. Alternatively, hand createJSONStorage a custom setItem that delegates stringify to a worker and resolves the write on the reply.

## Done when
- [ ] Profile a 600-story store with the perfProbe jank sampler during a fast round burst and confirm long frames drop after the change
- [ ] Verify a pagehide flush still writes the latest snapshot durably
