# Work order #399 — Kid SW swallows /parent/parent + clean portal URL
> milestone: bangla-ux-wave · branch: `feat/issue-399`

## Acceptance criteria (from the issue)
- [x] Browser with active kid SW navigates to /parent/ → dashboard (NOT the game)
- [x] /parent redirects to /parent/
- [x] /parent/login shows the sign-in form
- [x] Kid deep links point to /parent/
- [x] Parent + kid builds green, SW shows the denylist

## Goal
The "parent portal not accessible" bug was REAL and deeper than UX: the kid
PWA's service worker (scope "/") registered a blanket navigation fallback to
the game's index.html with NO denylist, so it intercepted EVERY navigation on
the origin — including /parent/* — and served the GAME shell. A browser with
the SW active saw the game at /parent/parent; curl (no SW) returned the portal,
which is why earlier checks looked green.

## What shipped
- **`apps/kid/vite.config.ts`** — `navigateFallbackDenylist: [/^\/parent\//, /^\/admin\//]`.
  The kid SW now lets the sibling apps fall through to nginx. Verified in the
  compiled `dist/sw.js`:
  `NavigationRoute(createHandlerBoundToURL("/index.html"),{denylist:[/^\/parent\//,/^\/admin\//]})`
- **Parent URL cleanup** (the "/parent/parent" gimmick):
  - `apps/parent/app/page.tsx` = DASHBOARD (landing at /parent/), moved from
    `app/parent/page.tsx`; its "Go to login" → `/login`.
  - `apps/parent/app/login/page.tsx` = LOGIN (at /parent/login), moved from
    `app/page.tsx`; its "Open dashboard" → `/` (auto-basePath → /parent/).
  - Fix import depth after moves (`../lib/api` ⇄ `../../lib/api`).
- **`apps/kid/src/App.tsx`** — deep links `/parent/parent` → `/parent/`.
- **`infra/deploy/nginx.conf`** — `location = /parent { return 302 /parent/; }`
  and `location = /admin { return 302 /admin/; }` so the no-slash paths can't
  fall into the game SPA.

## Notes
- Parent SW (scope /parent/) is network-first + cached shell fallback; with the
  dashboard now at index.html the offline fallback serves the dashboard's
  sign-in gate — correct.
- Parent static export emits `out/index.html` (dashboard) + `out/login.html`;
  nginx `try $uri.html` already resolves both.
- Live after release: browser → https://kids.munna-khan.xyz/parent/ shows the
  dashboard, /parent/login the form. Existing installed PWAs pick up the new SW
  via autoUpdate + clientsClaim, but a HARD refresh (or uninstall/reinstall the
  PWA once) is the clean way to drop the old scope-"/" SW interception.
