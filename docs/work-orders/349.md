# #349 — Perf: preconnect/priority for first paint

**Status:** ✅ done (PR pending → issue CLOSE)

## Problem

First paint should land on the real look immediately. Acceptance:
**fastest path measured** · **no FOUC**.

## Fix

First-paint priority hints in `index.html`.

- **Preload the two fonts the first screen actually uses** — `Baloo2-500.woff2`
  (65K, the title/display face) and `Nunito-400.woff2` (11K, the body face),
  each `<link rel="preload" as="font" type="font/woff2" crossorigin>`. They're
  fetched at the highest priority the instant the HTML parses, instead of
  waiting behind the stylesheet — so `font-display: swap` (kept, never blocks
  text) swaps to the real face after ONE fast same-origin fetch. Effectively
  no FOUC.
- **Preconnect is deliberately a no-op** — the whole app is same-origin and
  offline-first (fonts, JS, CSS, icons all local), so there are zero
  cross-origin requests to warm up. The honest fastest path is same-origin
  assets + font preload; documented in a comment so nobody adds a useless
  `preconnect` later.
- Vite already emits `modulepreload` for the app chunks; the engine stays a
  lazy dynamic chunk (#15) — nothing further to hint.
