# #126 — Guardrail: CI secrets hygiene scan

**Status:** ✅ released in 0.26.14 (2026-08-13)

## Problem

A `git add .` on the wrong directory could commit a hardcoded key, token, or
private key and ship it silently. The repo already gitignores `.env*`, but
there was no gate that fails a PR if a secret-shaped value lands in the
tracked tree.

## Fix

New zero-dependency `scripts/secret-scan.mjs` + a CI job:

- Scans **tracked files only** (`git ls-files`), never the working tree — a
  local uncommitted `.env` can't leak.
- Shape-detects the classic mistakes: AWS `AKIA…`/`ASIA…` access keys, AWS
  secret access keys, `-----BEGIN *PRIVATE KEY-----` blocks, GitHub
  `ghp_…/gho_…/ghu_…/ghs_…/ghr_…` tokens, and assignment lines carrying
  40+ alnum runs next to a key/token/secret identifier.
- `ALLOWLIST` map with an inline reason per exempted file (the scanner itself,
  docs, build files). No blanket ignores.
- `.github/workflows/ci.yml` → new `secret-scan` job (parallel, no core-dep)
  runs on every PR. Fails closed: exit 1 on any hit.
- `docs/RELEASING.md` → gate table documents the new job.

## Files
- `scripts/secret-scan.mjs` — new gate
- `.github/workflows/ci.yml` — `secret-scan` job
- `docs/RELEASING.md` — gate table row
