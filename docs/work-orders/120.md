# #120 — CI: run oracle_team as a PR gate job

**Status:** in progress (2026-08-13)

## Problem

The oracle standup (35 automated roles) only ran at release time (inside
release.sh) and on the daily launchd job. A PR could merge with a catalog or
safety regression the oracle would have caught — the gate came too late.

## Fix

- **`--ci` mode in `scripts/team/oracle_team.py`** — skips the four box-only
  roles (Security Auditor, Monitoring Watch, Chronic-Issue Examiner,
  Precedent Recorder) that read `~/.tresha`, the local mem API on 127.0.0.1 or
  `launchctl` — none of which exist in GitHub Actions. Every code/catalog/
  visual role still runs and judges the actual tree; also skips the mem-learn
  post. Exit code still 1 on any ✖ → blocks the PR.
- **`.github/workflows/ci.yml`** — new `oracle` job (needs `build-core`, runs
  `python3 scripts/team/oracle_team.py --ci --no-page --silent`). A red role
  fails the job → merge blocked.

## Files
- `scripts/team/oracle_team.py` — `--ci` mode + box-only skip set
- `.github/workflows/ci.yml` — `oracle` PR gate job
