# #130 — AR numbers camera experiment (tech spike)

**Status:** ✅ done (PR pending → issue CLOSE)

## Problem

Research-only: can a kid point the camera at a number and have the app see it
and play with it — **on-device, offline, no ads**?

## Spike outcome

Decision recorded in `docs/AR_NUMBERS_EVAL.md`: use an **on-device digit
classifier** (ONNX Runtime Web + a tiny per-script CNN) instead of a full OCR
engine. Tesseract.js would add ~15 MB of traineddata per language; a quantized
digit CNN is ~50–500 KB and extends per-script — matching the locale-pack
architecture's `digits: DigitSet` config (#131), so a new language is a model
asset, not a rewrite. Camera via `getUserMedia`; inference throttled; nothing
leaves the device.

**Why doc-only (no code this pass):** the spike's own gate is "tech spike
only", and verifying real camera recognition needs a physical device — which
cannot be tested from the pipeline. The doc records the decision + risk list
(iOS Safari camera, Bangla dataset licensing, bundle budget, 2GB Android perf)
and a "done when" checklist so the build wave can pick it up with a scheduled
device test on the operator's own hardware.
