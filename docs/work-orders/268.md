# #268 — Guardrail: no console.log in prod bundle

**Status:** in progress (2026-08-13)

## Problem

Debug logging (`console.log/warn/debug/info/trace`) in shipped frontend code
would go straight to every kid's device console — noise, and a habit that
masks real bugs. There was no gate stopping it.

## Fix

New section ⑤ in `apps/kid/scripts/audit.mjs` — **fail-closed** console scan:

- Walks every shipped frontend dir (`apps/kid/src`, `apps/parent/app`,
  `apps/parent/lib`, `apps/admin/src`) and fails the audit on any
  `console.log|debug|info|warn|trace` call, with file + snippet.
- `console.error` on a genuine error path is allowed (existing
  gameHost.ts/neuralVoice.ts watchdog uses are legit) — the scan targets the
  debug-logging class, not error reporting.
- The audit already runs in CI (`audit` job) → the gate is live on every PR.
