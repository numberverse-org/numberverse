# #135 — Optional parent phone notifications bridge (spike)

**Status:** ✅ done — decision doc (build wave scheduled)

## Problem

Weekly-summary push notifications for the parent's phone. Issue's Done when:
**requires sync** + **no analytics**.

## Spike outcome

Decision recorded in `docs/PARENT_NOTIFS_EVAL.md`: **Web Push (VAPID) via the
kid app's existing service worker** (`vite-plugin-pwa` → `registerSW` already
present). Standards-based, no APNs/FCM accounts; E2E-friendly (body = the same
`WeeklyOut` aggregates the panel already shows — mastery + coins, no
voice/face/raw answers); opt-in toggle in the parent panel, rendered only with
a parent session → genuinely *requires sync* (✅ #9 shipped the precondition).

**Why spike → build wave, not full code this pass:** delivery can't be
verified without live infra — a VAPID keypair has to be generated + configured
on the operator's box (env), and delivery needs a real phone (iOS 16.4+
installed-PWA / Android Chrome). That's the same standing rule as #130 (AR
camera) and #139 (QR scan): pipeline gates cover the repo; physical-device
checks happen on the operator's own hardware. The doc records the comparison,
the iOS-support risk, the server/client build sketch, and a "done when"
checklist so the build wave can pick it up directly.
