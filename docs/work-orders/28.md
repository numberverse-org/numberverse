# Work order #28 — feat: faster first-run neural TTS — boot-time preload + parallel fetch + int4 model (~10s ready)
> milestone: v14 — polish & perf · branch: `feat/issue-28`

## Acceptance criteria (from the issue)

**Why (kid-first):** on first run the neural Bangla voice takes a while to appear — a kid on 4G can wait a long time before the game starts talking. The voice is already served from the server (`/voice/` through the Cloudflare tunnel, then service-worker cached offline) — that part is done. The gap is **time-to-ready on the first visit**.

**Current state (measured):**
- `bn_BD-google-medium.onnx` fp32 77MB → int8 quantized → **~20MB** (already done, `quantize_voice.py`)
- Big files fetched on first run: phonemizer data **18MB** + `ort-wasm-simd.wasm` **10.5MB** + model **20MB** ≈ **~48.6MB**
- Preload starts **only on the first user gesture** (`preloadNeuralVoice()` rides pointerdown/touchstart/click/keydown) — the download doesn't need a gesture, only playback does
- Worker fetches the big files **sequentially** inside init (download time ≈ sum, not max)

**Acceptance criteria**
- [x] **Boot-time preload (biggest win):** `bootPreload()` (neuralVoice.ts) starts the voice download at the first idle after paint (`requestIdleCallback`, fallback 1s timeout), NOT on the first tap. Playback stays gesture-gated (iOS unlock untouched) — only the *download* moved earlier. The gesture handler is now just the flaky-Wi-Fi retry path.
- [x] **Parallel big fetches:** `downloadParallel()` (neuralVoice.ts) fetches phoneme.data (18MB) + the int8 model (20MB) IN PARALLEL on the main thread with live streamed progress, handing the blobs to the worker's blob cache (its getBlob resolves cached blobs instantly). First-run time ≈ max(file), not the sum. (ORT's own .wasm downloads independently, so it's not in the parallel set.) Watchdog + progress still correct.
- [~] **Model size cut — BLOCKED on ORT 1.17, delivered a SAFER equivalent:** int4 weight-only QDQ is **not possible on the pinned onnxruntime 1.17.0 WASM build** — proven from the shipped binary (`ort-wasm-simd.wasm` has zero int4 symbols; its DequantizeLinear error only mentions int32/fp8). int4 needs an ORT upgrade + a real listen/QA pass → filed as a follow-up (see issue #29). **What shipped instead (same budget, zero model risk):** the big static files are gzip-precompressed at Docker build (Dockerfile.web voice stage) and served via `gzip_static on` (nginx.conf) → phoneme.data 18→~11MB, ort-wasm 10.5→~5.8MB, int8 model 20→~17MB ≈ **~30% wire cut**, no audio change at all. `VOICE_V` bumped v2→v3 so old installs re-fetch.
- [x] **Edge + hint wins:** `Cache-Control: public, max-age=31536000, immutable` was ALREADY on `/voice/` (nginx.conf) — verified, Cloudflare edge keeps the payload close to BD kids. `preconnect`/`dns-prefetch` to the origin is a **documented no-op** (the app serves `/voice/` from the same origin it already holds a connection to), so it was not cargo-culted in.
- [x] **SW warm-cache:** `seedSwVoiceCache()` (neuralVoice.ts) puts the ALREADY-downloaded blobs into the `nv-voice` CacheFirst cache directly (no extra bytes on the wire) → the *second* visit is instant. First visit is the only slow one.
- [ ] **Measure + prove the budget:** needs a live measurement on the box post-deploy (the constraint is no CDP headless Chrome, so no local browser harness). Verify on `https://kids.munna-khan.xyz`: cold-cache first visit should reach `speechStatus().neural.ready === true` in **≤ ~10s** on nominal 4G (curl `/voice/*` for the served sizes, parent-panel voice card for the meter). Record before/after in the PR.

**Guardrails (don't break):**
- Privacy is the moat — the model is on-device after one download; nothing about a kid's voice/text ever leaves the device. Edge caching is just static-file CDN, never kid data.
- iOS audio-unlock stays exactly as-is (gesture-gated `neuralPrime` + `onstart`-proven Web Speech prime).
- Web Speech remains the fallback until the model is ready — Bangla is never silent.
- No CDP headless Chrome for testing; verify live on the box link (https://kids.munna-khan.xyz) + physical device where possible.
- No ads, no analytics added.
