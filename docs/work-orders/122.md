# #122 — Postgres backup schedule to box disk

**Status:** ✅ shipped 2026-08-13 — merged (#420); cron live on box; housekeeping rides the next release.

## Problem

The box's `numberverse` database lived only in a docker volume — a bad
`docker compose` step or a full disk could destroy months of progress. No
automated dump existed.

## Fix

New `infra/backup/pg_backup.sh` + a daily crontab job on the box:

- **Dump** — `docker exec numberverse-demo-postgres-1 pg_dump -O` piped to
  gzip → `~/backups/numberverse/pg/numberverse-<ts>.sql.gz`, gzip-integrity
  verified, last-run marker appended.
- **Retention** — keeps the 14 newest dumps, prunes the rest.
- **Restore drill** — `--drill` restores the newest dump into a throwaway
  `postgres:16-alpine` container and asserts the table count matches live
  (then drops the container). Proven on the box: **live=12 drill=12 ✓**.
- **Schedule** — crontab `30 3 * * *` (quiet `CRON=1` mode), appending to
  `pg/cron.log`. Box already runs a 3am memory backup; pg lands at 3:30.
- **Scope safety** — targets ONLY the `numberverse-demo-postgres-1` container.
  The unrelated `shikho-db` container is never touched.

## Files
- `infra/backup/pg_backup.sh` — dump + retention + drill (versioned in repo,
  mirrored to the box at `~/numberverse-demo/infra/backup/`)
